# سرور کلید BM Hub

هر نفر یه کلید اختصاصی می‌گیره. کلید با اولین استفاده به اکانت روبلاکس همون نفر قفل میشه، می‌تونه تاریخ انقضا داشته باشه و هر وقت خواستی خاموشش می‌کنی (هاب روشنِ اون نفر هم حداکثر ۱۰ دقیقه بعد بسته میشه).
اسکریپت اصلی از مخزن **خصوصی** گیت‌هاب خونده میشه و فقط با کلید درست تحویل داده میشه.

## فایل‌ها
| فایل | چیه |
|---|---|
| `worker.js` | خود سرور (کلیدها، تحویل اسکریپت، API ادمین) |
| `admin.html` | پنل مدیریت (`/admin`): داشبورد، کلیدها، ساخت، فعالیت‌ها، ادمین‌ها، تنظیمات |
| `build.py` | این دو تا رو یه فایل می‌کنه: `dist/worker.js` |
| `dev.mjs` | نسخه‌ی محلی برای دیدن پنل (رمز `dev-password`، فقط روی همین کامپیوتر) |
| `dist/worker.js` | **همینو توی Cloudflare می‌چسبونی** |
| `test.mjs` | تست‌ها (`python tests_offline/run_all.py` خودش اجراشون می‌کنه) |

## راه‌اندازی (یه بار)

### ۱. توکن گیت‌هاب (فقط خواندن)
github.com → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
- Repository access: **Only select repositories** → `bm-hub`
- Permissions → Repository permissions → **Contents: Read-only**
- توکن رو کپی کن (فقط یه بار نشون داده میشه). به هیچ‌کس نده.

### ۲. Cloudflare
1. توی dash.cloudflare.com اکانت رایگان بساز.
2. **Workers & Pages → Create → Create Worker** → اسم: `bmhub-keys` → Deploy.
3. **Edit code** → همه‌ی کد رو پاک کن، محتوای `keyserver/dist/worker.js` رو بچسبون → **Deploy**.
4. **Storage & Databases → KV → Create** → اسم: `bmhub-keys`.
5. برگرد به Worker → **Settings → Bindings → Add → KV namespace** → Variable name: `KEYS` → همون KV که ساختی.
6. **Settings → Variables and Secrets → Add**:
   - `REPO` (Text) = `radingoodarzi/bm-hub`
   - `FILE` (Text) = `bm_hub_v3.lua`
   - `BRANCH` (Text) = `main`
   - `ADMIN_PASSWORD` (**Secret**) = یه رمز قوی
   - `GITHUB_TOKEN` (**Secret**) = توکن مرحله‌ی ۱
7. Deploy.

(اسم دکمه‌ها توی داشبورد Cloudflare ممکنه کمی فرق کنه.)

### ۳. امتحان
- برو `https://bmhub-keys.<اسم-اکانتت>.workers.dev/admin` → رمز → یه کلید برای خودت بساز (روز خالی = دائمی). لودرش خودش کپی میشه.
- توی Solara اجراش کن. باید هاب بیاد.

### ۴. بعد از اینکه کار کرد: مخزن رو خصوصی کن
github.com/radingoodarzi/bm-hub → Settings → General → پایین صفحه → **Change visibility → Private**.
از این به بعد لینک‌های قدیمی (`loader_v3.lua` و دانلود `bm.lua`) کار نمی‌کنن؛ همه، حتی خودت، با لودر کلیددار اجرا می‌کنن.

## پنل
- **ورود:** صاحب هاب با نام کاربری `owner` (یا خالی) و `ADMIN_PASSWORD`. ادمین‌ها با نام کاربری و رمزی که صاحب هاب توی صفحه‌ی «ادمین‌ها» براشون می‌سازه.
- ادمین‌ها کلید می‌سازن و مدیریت می‌کنن، ولی فقط کلیدهای خودشون رو پاک می‌کنن و به «ادمین‌ها» و «پشتیبان» دسترسی ندارن.
- هر کلید می‌تونه چند اکانت روبلاکس داشته باشه (پیش‌فرض ۱)، یادداشت داره و تلاش اکانت‌های دیگه ثبت میشه.
- «فعالیت‌ها» کارهای همه‌ی ادمین‌ها رو ۹۰ روز نگه می‌داره.
- پلن رایگان KV روزی ۱۰۰۰ نوشتن داره: هر اجرای هاب ۱ نوشتن، چک دوره‌ای هیچی.

## استفاده‌ی روزمره
- **کلید جدید:** صفحه‌ی ادمین → اسم + تعداد روز → «ساخت کلید» → لودرش کپی میشه → برای همون نفر بفرست.
- **خاموش کردن:** «خاموش کردن» (هاب روشنش حداکثر ۱۰ دقیقه بعد بسته میشه).
- **اکانتش رو عوض کرد:** «آزاد کردن اکانت» (اجرای بعدی به اکانت جدید قفل میشه).
- **تمدید:** «تمدید» و تعداد روز از امروز.
- **بعد از push نسخه‌ی جدید:** خودش حداکثر ۱ دقیقه بعد نسخه‌ی جدید رو میده؛ برای فوری، «گرفتن نسخه‌ی جدید هاب».

لودری که مشتری می‌گیره:
```lua
getgenv().BM_KEY = "BM-XXXX-XXXX-XXXX-XXXX"
loadstring(game:HttpGet("https://bmhub-keys.<اسم-اکانتت>.workers.dev/l"))()
```

## محدودیت‌ها
- همه‌ی ادمین‌ها یه رمز مشترک دارن و با اون رمز همه‌ی کارها رو می‌تونن بکنن.
- کسی که کلید معتبر داره متن اسکریپت رو دریافت می‌کنه و می‌تونه ذخیره‌ش کنه. مبهم‌سازی این رو سخت‌تر می‌کنه، ولی هیچ سیستمی صددرصد جلوش رو نمی‌گیره.
- اگه دامنه‌ی `workers.dev` جایی فیلتر باشه، مثل خود روبلاکس با VPN کار می‌کنه.
